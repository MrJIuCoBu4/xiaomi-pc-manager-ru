# Участие и сборка

Python 3.10+, без сторонних пакетов для установщика и тестов:

```powershell
py -3 -m unittest discover -s tests -v
py -3 tools/verify_package.py
py -3 tools/release.py --output ../dist
```

Не добавляйте в Git оригинальные или целиком изменённые DLL/EXE/PRI/JS/CSS Xiaomi,
личные резервные копии, декомпиляцию, пользовательские логи и скриншоты с серийными номерами.
Публичные `translations/` содержат таблицы перевода; их правки сами по себе ещё не перестраивают патч.

`tools/build_private.py --workspace <private-workspace>` — инструмент сопровождающего для текущей
структуры подготовленных исходных/конечных файлов. Он читает закрытые локальные копии вне репозитория,
создаёт copy/insert-дельты, проверяет каждый результат SHA256 и формирует каталог.
Для новой версии приложения нужно заново исследовать строки/методы и подготовить исходные/конечные файлы;
нельзя просто заменить номер версии или отключить проверку хеша.

Публикация нового релиза:
1. Запустить тесты и verify_package.py.
2. Проверить установку, повторную установку, OSD и откат на копии поддерживаемой сборки.
3. Провести проверку в работающем приложении на тестовом ноутбуке.
4. Собрать ZIP и SHA256SUMS, создать тег и предварительный GitHub Release.
5. После обратной связи и исправлений выпускать стабильный релиз.

Версионирование: перевод/раскладка используют версию патча отдельно от версии Xiaomi.
Первый публичный пакет — 1.4.4-rc.1, а не обещание полной поддержки всех устройств.

Исходные дополнительные CSS-правила доступны в `translations/layout.css`, подписи и области OSD —
в `translations/osd.json`. `tools/localize_osd.py` — дополнительный авторский инструмент для локальных
PNG Xiaomi; требует Pillow и шрифт Segoe UI Semibold из установленной Windows. Он не входит в путь установки
и не скачивает исходные значки/шрифты. Не публикуйте его выходную папку целиком.

Для небольшого обновления UI поверх существующего каталога используйте `tools/build_update.py`
с `--workspace` и `--base-catalog` (сохранённый каталог предыдущего релиза). Базовый архив не меняется;
новые дельты публикуются отдельным архивом из `supplementalArchives`. Устаревшие записи учтены в `retiredEntries`.
